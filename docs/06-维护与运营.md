```powershell

python -m unittest tests.test_privacy -v
```

## 3. superagent 常驻维护

### 3.1 角色分工

- **orchestrator / worker**：`dsh-superagent` 跑在本机，source 指向本仓库。
- **agent 账号**：`LingYS-14-agent`（仓库协作者，push 权限）。
- **人审合并**：所有 PR 由 `LingYS-14` 账号审阅后合并；agent 不自动合并、不自动批准。
- 工单来源：在 issue 下评论 `@LingYS-14-agent <请求>`（agent 账号需要被 @ 才会收到通知）。
- 合并后：插件会检测到 PR merged，自动在原 issue 下评论并关闭（`dsh-superagent:auto-close:<PR>` 幂等标记）。

### 3.2 服务栈（四层）

| 层 | 位置 | 作用 |
| --- | --- | --- |
| 服务本体 | `scripts/dsh-superagent.ps1` + profile `superagent` | 面板 `http://127.0.0.1:3082`，state 在 `<HOME>\.dsh\state\superagent` |
| 整点自愈 | DSH 内每小时 schedule | 跑 `status`，退出码 1 时 `restart -RespectStop` |
| 15 分钟看门狗 | Windows 计划任务 `KISEKI Superagent Watchdog` | 见 3.3，DSH 重启把服务连带杀掉后能在 15 分钟内拉回来 |
| 人审合并 | GitHub | 唯一的人工环节 |

### 3.3 看门狗

- 脚本：`C:\AI\dsh-superagent-prototype\scripts\superagent-watchdog.ps1`
- 隐藏启动器：`C:\AI\dsh-superagent-prototype\scripts\superagent-watchdog.vbs`（wscript 以
  `Run(..., 0, False)` 静默拉起 PowerShell，**不会闪黑色终端窗口**）
- 计划任务：`KISEKI Superagent Watchdog`，每 15 分钟一次，`RunLevel=HighestAvailable`。
  之所以要 Highest：superagent 服务是 DSH 的子进程（High 完整性），普通权限的计划任务
  读不到它的命令行，会误判成「服务已停止」而每 15 分钟尝试重启并弹窗。
- 逻辑：`status` 退出 0 → 什么都不做；退出 1 但仍有 pid → 视为启动中，最多等 150 秒；
  真正掉了才 `restart -RespectStop`；`manually_stopped=true` 时保持停止。
- 日志：`C:\AI\dsh-superagent-prototype\.artifacts\superagent-watchdog.log`

手动检查：

```powershell
schtasks /Query /TN "KISEKI Superagent Watchdog" /FO LIST /V
powershell -NoProfile -ExecutionPolicy Bypass -File C:\AI\dsh-superagent-prototype\scripts\dsh-superagent.ps1 -Profile superagent status
```

### 3.4 已知限制

- 服务是 DSH 的子进程，**DSH 桌面重启会连带杀掉它**；DSH 重启后 15 分钟内由看门狗恢复。
- 计划任务是用户级任务，需要该用户已登录 Windows 才会运行。
- 如果手动 `stop` 过（`manually_stopped=true`），看门狗不会强行拉起，需要显式 `-Action start`。
